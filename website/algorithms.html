Dense linear algebra: peigen.linalg

The functions follow NumPy's conventions: a 1D right-hand side returns a 1D solution, and shapes match numpy.linalg. Where both are available, method="auto" picks LAPACK; the release wheels always link it.

Sparse Cholesky: sparse.cholesky

sparse.cholesky(a, mode="ldlt", ordering="amd", lower=True, shift=0.0) factors P (A + shift·I) Pᵀ once and returns a reusable SparseCholesky. Only one triangle of A is read, so you can pass just that triangle. It needs no SuiteSparse.

ModeFactorizationEigen classUse it for
"ldlt" (default)L D Lᵀ, no square rootsSimplicialLDLTSPD matrices with low fill: 2D meshes, graph Laplacians, banded systems. Solves with many right-hand sides use a blocked kernel.
"llt"L LᵀSimplicialLLTClassic Cholesky. Raises if the matrix isn't positive definite, so it doubles as a definiteness test.
"multifrontal" experimentalPivoted L D Lᵀ, with D made of 1×1 and 2×2 blocksMultifrontalLDLTHigh-fill problems (3D meshes) and symmetric indefinite matrices. Solves with several right-hand sides use a supernodal blocked kernel.

Orderings

ordering="amd" (approximate minimum degree) reduces fill-in and is the right choice almost always. ordering="natural" keeps the input order, which is only useful for banded matrices or debugging.

Indefinite matrices: use mode="multifrontal". "ldlt" doesn't pivot for stability, so it can be inaccurate or fail on them. Multifrontal's threshold pivoting doesn't rescale the matrix, so equilibrate badly scaled input first.

One-shot use: sparse.solve(A, b, method="cholesky") is the same as sparse.cholesky(A).solve(b).

Sparse LU: sparse.factorize

sparse.factorize(A) wraps Eigen's SparseLU: a supernodal LU with partial pivoting and a COLAMD column ordering, for general square matrices. It returns a SparseFactorized object whose solve(b) accepts 1D or 2D right-hand sides. sparse.solve(A, b) (method="auto" or "lu") does the same in one call.

Iterative solvers: sparse.solve

method=MatrixEigen classPreconditioners
"cg"Symmetric positive definiteConjugateGradient"none", "jacobi" (diagonal), "ichol" (IncompleteCholesky, zero fill); "ilu" (IncompleteLUT) is deprecated
"bicgstab"General squareBiCGSTABDiagonal (Eigen's default)

tol is the relative residual ‖Ax − b‖ / ‖b‖ (default 1e-8), and maxiter defaults to 2n. The solvers raise RuntimeError if they don't converge. sparse.solve_stats(A, b, method="cg", ...) returns the iteration count, Eigen's residual estimate and the true residual, for comparing preconditioners.

Convergence is checked against the true residual. Eigen stops on a recursively updated residual, which can drift away from b − Ax (BiCGSTAB on convection-dominated problems is the usual victim). pEigen recomputes the true residual after every solve; if it is more than 10× above tol, the solver restarts from where it stopped (up to 5 times, within maxiter) and raises RuntimeError if that doesn't recover. A tol below what double precision can reach for your problem raises rather than returning a less accurate answer.

Preconditioning CG: use "ichol", a symmetric zero-fill incomplete Cholesky computed in the matrix's own ordering. On a 100×100 5-point Laplacian it cuts CG from 186 to 77 iterations. "ilu" (IncompleteLUT) is not symmetric, which CG assumes, and at the default ilu_fill_factor=10 it fails to converge even on that Laplacian; with CG it now emits a DeprecationWarning and will be removed in 3.0. If you solve the same SPD matrix many times, sparse.cholesky is usually faster than any CG.

Conventions

  • Real double precision. Everything runs in float64. Integer and float32 inputs are converted; complex inputs raise TypeError rather than silently dropping the imaginary part.
  • Any SciPy sparse format. *_matrix or *_array, int32 or int64 indices. Unsorted or duplicate entries are canonicalized on a copy; your matrix is never modified.
  • Size limit. Sparse dimensions and nonzero counts must fit in 32-bit indices; larger matrices raise ValueError.
  • Errors. ValueError for bad shapes or arguments, numpy.linalg.LinAlgError when a Cholesky factorization breaks down, RuntimeError when an iterative solver doesn't converge or a sparse LU fails.
  • Licensing. pEigen is MIT. It compiles Eigen with EIGEN_MPL2_ONLY, so the wheels contain only MPL-2.0 Eigen code.
