Benchmarks

pEigen timed against SciPy, NumPy and CHOLMOD on the same machine, including the cases where pEigen is slower.

Summary

1.8–6×
faster sparse Cholesky factorization than SciPy's default splu on 2D meshes and graphs
3–9×
faster 3D-mesh factorization with mode="multifrontal" than simplicial LDLᵀ
1.1–4.4×
faster 32-RHS solves than CHOLMOD's best mode, on all 11 problems

Where pEigen is a good fit

  • Sparse SPD factorizations on 2D meshes and graphs, and any workload that solves many right-hand sides with one matrix.
  • Refactorizing with the same pattern, and log-determinants.
  • Dense solve and qr: 1.0–2× faster than NumPy at moderate and large sizes.
  • Iterative CG and BiCGSTAB: 1.1–3.7× faster than SciPy, mostly from lower per-iteration overhead.

Where something else is faster

  • Factorizing 3D meshes: CHOLMOD's supernodal mode is 1.3–3.6× faster than pEigen's multifrontal mode single-threaded, and further ahead with threads.
  • Sparse products: SciPy's @ is 2.3–2.7× faster than spmm and 1.5–2.3× faster than spspmm.
  • General sparse LU: SciPy's SuperLU is 7–30% faster than SparseLU.
  • Dense matmul: 6–16% slower than NumPy (both call Accelerate).

Reading the results

  • Low fill (2D meshes, graphs): the default ldlt factors 1.8–6× faster than SciPy's default splu, 1.2–2× faster than splu in symmetric mode (even with it on the 512² grid), and 9–34% faster than CHOLMOD's simplicial mode. multifrontal comes within about 15% of CHOLMOD's supernodal mode.
  • High fill (3D meshes): simplicial methods fall behind. multifrontal factors the 40³ grid in 1.29 s against 11.3 s for ldlt, but CHOLMOD's supernodal mode takes 0.36 s. Across the 3D meshes CHOLMOD is 1.3–3.6× faster. Its default ordering strategy, which can choose nested dissection, also stores 38% fewer nonzeros on 40³ than pEigen's AMD-ordered factor.
  • Solves: with one right-hand side, multifrontal ranges from 1.4× slower to 1.2× faster than CHOLMOD, and ldlt is 1.6–3.5× slower. With 32 right-hand sides, multifrontal was the fastest solver on every problem. Its first many-RHS solve after each factorization builds a blocked copy of L, a one-time cost of 0.25–0.65× the factorization.

Sparse routines vs SciPy

2D grid operators from 1,024 to 16,384 unknowns: a 5-point Laplacian (SPD, for CG and the products) and an upwind advection–diffusion operator (nonsymmetric, for LU and BiCGSTAB). Products and BiCGSTAB use 8 right-hand sides; CG uses 1. Iterative solvers run to a relative residual of 1e-8, and both libraries' true residuals were checked to reach it. The ratio is SciPy's time divided by pEigen's.

Methodology

  • Machine: Apple M1 Pro (10 cores), macOS.
  • Software: pEigen 2.1.0 (Eigen master, 2026-11-22), Python 3.14.6, NumPy 2.5.0 and SciPy 1.18.0 (both on Accelerate), scikit-sparse 0.5.1 for CHOLMOD.
  • Timing: median (p50) of repeated runs after warm-up, wall-clock, one benchmark at a time on an otherwise idle machine.
  • Threads: the sparse Cholesky comparison is single-threaded (OMP_NUM_THREADS, VECLIB_MAXIMUM_THREADS and OPENBLAS_NUM_THREADS set to 1). The dense and sparse comparisons use default threading.
  • Factor time includes symbolic analysis (ordering and elimination tree) plus the numeric factorization. Refactor is the numeric phase only, with the same pattern and new values.
  • Measured on 2026-11-25. Results on Linux with OpenBLAS will differ, especially for dense routines.

Reproduce

The scripts live in the repository's benchmarks/ folder:

bash
git clone --recurse-submodules https://github.com/TtheBC01/pEigen.git
cd pEigen
python -m pip install -e ".[benchmark,sparse]"
python benchmarks/bench_dense.py
python benchmarks/bench_sparse.py
OMP_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  python benchmarks/bench_cholesky.py

The CHOLMOD columns need scikit-sparse, which builds against SuiteSparse; DEV.md shows how. Without it, bench_cholesky.py compares against SciPy only. Run the benchmarks one at a time: concurrent runs compete for cores and memory bandwidth and skew each other.
